# 使用文档（USER GUIDE）

面向日常使用者：部署、管理台各页面怎么用、auto 智能路由/降级/付费保护的实操、常见问题。

---

## 1. 部署

### 1.1 PC（Linux / macOS / WSL）

```bash
pip install -r backend/requirements.txt
bash start.sh              # 后台启动；首次启动自动建库 + 生成默认密钥
bash start.sh logs 30      # 查看默认密钥（sk-gw- 开头）
```

### 1.2 Termux（Android 手机本地跑）

```bash
pkg update && pkg install python
bash termux-setup.sh       # ★ 必跑一次：自动从 TUR 源装 pydantic-core 预编译 wheel
bash start.sh foreground   # 前台运行（手机上推荐，退出 Termux 即停止）
# 或 bash start.sh        # 后台运行
```

> 为什么需要 termux-setup.sh：`pydantic-core`（FastAPI 依赖的 Rust 扩展）在 PyPI 没有 Android 平台的预编译包，直接 pip 会因缺 Rust 工具链失败；该脚本从 Termux User Repository 拉取官方交叉编译的 aarch64 wheel，全程零编译。

### 1.3 管理脚本

```bash
bash start.sh start|stop|restart|status|logs
bash start.sh logs follow   # 实时日志
bash start.sh foreground    # 前台运行
```

### 1.4 FRP 内网穿透（外网访问手机/内网机器）

1. 找你的 FRP 服务商（ChmlFrp、SakuraFrp、自建 frps 等）拿到：服务器地址、端口、用户、token、远程端口
2. 参考 `frpc.example.ini` 模板，把配置粘贴到管理台「系统设置 → FRP 内网穿透」页，改好保存
3. 点「启动」，状态变运行中即可通过 `http://服务器地址:远程端口` 访问
4. 可勾选「网关启动时自动启动 FRP」

⚠ **只穿透 API 端口（默认 9010），管理台端口（默认 9009）绝不可穿透。**

### 1.5 修改端口

管理台「系统设置」改 API/管理台端口（重启生效）；或环境变量 `GATEWAY_PORT`、`GATEWAY_ADMIN_PORT`。

## 2. 管理台 8 个页面

| 页面 | 用途 |
|---|---|
| **仪表盘总览** | 今日请求/成功率/token 统计、模型状态网格、实时监视、告警、快捷操作 |
| **模型监控** | 模型健康状态、别名映射、健康检测、**↑↓ 排序（= 降级顺序）**、**auto 开关/规则/付费排除** |
| **上游渠道** | 添加/编辑渠道（协议、权重、并发、重试、熔断、代理、**付费标记**）、拉取模型、连通测试 |
| **客户端密钥** | 生成 sk-gw- 密钥、额度与周期重置、RPS、模型/IP 白黑名单 |
| **路由&分流** | 全局选路策略（加权轮询/最少并发/最低延迟/故障转移/轮询）、条件路由规则 |
| **调用日志** | 全量请求日志（可看请求/响应 payload）、筛选、导出 CSV |
| **错误日志** | 失败请求子集，定位上游问题 |
| **系统设置** | 端口、反代规则、FRP、CORS、限流、检测间隔、日志保留、配置导入导出、主题 |

## 3. 上游渠道配置

「上游渠道 → 新建」：

- **API 端点**：OpenAI 兼容填 base_url（如 `https://api.xx.com/v1`；不带 `/v1` 会自动补，已含 `/v4` 等版本段则不补）；Claude 协议选 anthropic
- **模型管理**：保存后点「拉取模型」自动从上游 `/v1/models` 补录；也可手动添加
- **付费标记**：按月收费/按量付费的渠道建议打开「💸 付费渠道」，auto 会默认避开它
- **权重/并发/重试**：多渠道负载时调权重；并发限制防打爆上游；重试状态码默认 429/5xx

## 4. 模型监控与降级顺序

- 每个模型一行，**列表顺序即备选降级顺序**（默认按添加先后）
- 点 **↑ / ↓** 调整顺序：排在越前，主模型失败时越先被降级使用
- 「单模型测试」发真实请求验证；「检测此渠道全部模型」批量健康检查
- 状态含义：🟢 在线 · 🟠 限速/超时 · 🔴 离线 · ⚪ 不存在（从未检测为未知）
- 被上游判定「模型不存在/不可用」的模型自动冷却 60s（期间 auto 与降级自动绕过），健康检测确认不可用会冷却更久

## 5. auto 智能路由

模型监控页顶部「🎯 auto 智能路由」卡片：

1. **总开关**：开启后客户端 `model` 填 `auto` 即可使用；关闭后请求 auto 报模型不存在
2. **💸 排除付费渠道**（默认开）：auto 挑选时跳过标记付费的渠道
3. **📋 规则路由**：按问题内容选模型
   - 新增规则：关键词（如 `翻译`）→ 目标模型（如 `hy3`）→ 优先级（数字小先匹配）
   - 用户消息**包含关键词**时，auto 优先用该模型；该模型不可用自动健康度兜底
   - 命中时响应头带 `X-Gateway-Auto-Rule`，方便确认
4. auto 全部候选失败会换下一个重试（最多 3 次），仍失败返回明确错误

## 6. 客户端密钥

- 生成后以 `sk-gw-` 开头，客户端 `Authorization: Bearer sk-gw-xxx` 调用
- 四项额度（请求数/总 token/输入/输出）+ 周期重置（每日/每月/不限）
- **模型白名单**：填了就只能用白名单内模型；若要用 `auto`，需把 `auto` 也加进白名单
- IP 白名单、key 级 RPS、用量告警阈值按需配置

## 7. 常见问题（FAQ）

**Q：忘记默认密钥了？**
`bash start.sh logs 50` 查看；或在管理台「客户端密钥」重新生成。

**Q：管理台打不开 / 显示 Missing API key？**
确认访问的是 **9009** 管理台端口而不是 9010；9010 只提供 API。

**Q：某个模型一直失败？**
错误日志看具体报错；404/「service info not found」类为模型下线，删掉或换模型；429 为限流，网关会自动冷却重试。

**Q：想指定模型失败就报错、不要自动降级？**
系统设置关 `model_fallback`。

**Q：数据库在哪？怎么备份？**
`data/gateway.db` 单文件，停网关后直接复制即可备份。

**Q：怎么彻底重置？**
停止网关 → 删除 `data/gateway.db` → 重新 `bash start.sh`（自动重建空库并生成新默认密钥）。

**Q：Termux 后台运行被杀？**
用 `bash start.sh foreground` 配合 Termux 的 wake-lock（通知栏获取电池优化白名单），或使用 `tmux`。
